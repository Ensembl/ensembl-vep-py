ensembl.vep.workflow.executor module#

Payload execution: who runs the work, and how the work is grouped into payloads.

Three things, one per step of a run’s spine. ExecutionSpec is what the configuration asked for. PayloadIterator groups a source’s records into the payloads one unit of work holds. Executor runs them against a Worker, serially or across processes, and yields the results in payload order whatever order they finish in.

multiprocessing_context()[source]#

Return the multiprocessing context to run workers in.

auto means fork wherever a forked worker is safe, which is what keeps the parallel path fast: a forked worker inherits the loaded package, its catalogue and its caches, while a spawned one re-imports all of it. Measured on 10,000 ClinVar variants across four workers, spawning cost about 30% of wall time. Threads are the exception – forking a process that already has them is unsafe – so a threaded run takes the platform default instead.

Return type:

BaseContext | None

class ensembl.vep.workflow.executor.Executor[PayloadT, ResultT](*, specification, worker_factory, payload_iterator)[source]#

Bases: Generic[PayloadT, ResultT]

Ordered payload executor with one worker per process.

A worker is built after its process starts and then reused, so what the executor transports is the factory rather than the worker: a worker holds open sources and warm caches that neither cross a process boundary nor survive a rebuild. The serial path runs the same way, against a worker of its own in the calling process, so there is one execution contract rather than two.

Variables:

  • specification (ExecutionSpec) – Process and queue configuration.

  • worker_factory (Callable[[], Worker[PayloadT, ResultT]]) – Construct one worker. It is what crosses to a worker process, so it has to pickle; the worker it builds does not.

  • payload_iterator (Iterable[PayloadT]) – The payloads to run, in input order, each serialisable whenever processes exceeds one. A run passes a PayloadIterator.

class ensembl.vep.workflow.executor.PayloadIterator[RecordT](*, records, batch_size, region_of=None)[source]#

Bases: Generic[RecordT]

One source’s records, grouped into the payloads an executor runs.

Here rather than in the source being read: a source says what a record is and which region it sits on, and how many records make one unit of work is an execution setting (buffer_size).

Variables:

  • records (Iterable[RecordT]) – The records to group, in input order. Closed with this iterator, since reading them is what holds the input open.

  • batch_size (int) – The most records one payload may hold.

  • region_of (Callable[[RecordT], str] | None) – Name the sequence region a record sits on. A payload then never spans two regions, which is what a worker’s annotation tracks prime from – one region’s features, fetched once for the whole payload. None groups by size alone, for records that name no region.
