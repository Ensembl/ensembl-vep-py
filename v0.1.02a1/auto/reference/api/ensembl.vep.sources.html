ensembl.vep.sources.build module#

Source construction from run configuration.

Two kinds of source, named apart on purpose: the input source holds the variants being annotated, and the annotation sources hold what they are annotated against. Perl VEP draws the same line – its input is a Parser and its annotation sources come from AnnotationSourceAdaptor::get_all, which reads the configuration and returns whichever set of sources it names (a cache, a database, a GFF3/GTF file, custom files).

These are functions rather than a class holding the set: a run’s sources are built once, wired to each other, and then used directly by whoever asked for them. The one thing they must share is the reference sequence and the synonym map, which is why those are built first and passed in.

There is one builder per kind of annotation source rather than one call returning the whole set. Each annotation track builds the source it annotates against, so nothing has to pick its own source out of a list of everything configured.

Which input format to read is decided here, by name, against the closed set in common/constants.py. One conditional in one place, rather than a registry each source registers with: the configuration package offers the same names as --format choices and cannot import the sources, which import it.

ensembl.vep.sources.feature_source module#

The feature source contract.

Reading and model building are two halves. The record getters answer in whatever the source’s own records are – what the format holds, before anything has been interpreted – and records_to_features turns a set of them into models. The feature getters are those two composed, which is why they are concrete here: a source implements the record half and gets the feature half. A format that assembles one feature from several records (GFF3, GTF) overrides the feature getters, because a record at a time is not enough to build anything complete.

class ensembl.vep.sources.synonym.ChromosomeSynonyms(*, by_name=dict())[source]#

Bases: object

Sequence-region names that name the same region, held once for the whole run.

Perl VEP keeps one synonym map per run and asks it for every source (BaseVEP:: chromosome_synonyms); a name is not a synonym of a source, it is a synonym full stop, and which spelling a given source wants is decided by that source’s own valid names. Keeping one map is what lets 22 -> NC_000022.11 serve the FASTA and the transcript file at once, in whichever direction each of them needs.

Variables:

by_name (Mapping[str, frozenset[str]]) – Every name, mapped to the other names for it.

by_name: Mapping[str, frozenset[str]]#
classmethod from_file(path)[source]#

Read a synonyms file in Perl VEP’s format.

Each line lists whitespace-separated names for one region. The first name is the reference spelling and every later name is a synonym of it, recorded in both directions – as Perl does, so two synonyms of one reference name are not made synonyms of each other.

class ensembl.vep.sources.synonym.SequenceRegionResolver(*, source_names, synonyms=ChromosomeSynonyms())[source]#

Bases: object

Resolve uploaded sequence-region names against one source.

Perl’s BaseVEP::get_source_chr_name in our shape: an exact source name wins, then a synonym the source declares, then the conventional case-insensitive chr prefix adjustment, and an unresolved name keeps its uploaded spelling. Resolution is memoised per instance, which is why each source gets its own resolver over the shared synonym map.
