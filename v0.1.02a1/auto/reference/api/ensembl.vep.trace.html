ensembl.vep.trace package#

Derivation traces for consequence annotations.

A trace records the facts, rule verdicts, subsumption decisions, and emitted terms for one overlap. The package sits below annotators because fact evaluation and caches both depend on its event types.

Only annotation and event types are re-exported here. Reconstruction and aggregation depend on higher layers that already import this package, so import those features from their modules to avoid dependency cycles. Comparing and summarising a finished trace is not tracing at all: that lives in ensembl.vep.explain.

Submodules#

ensembl.vep.trace.annotation module#

Completed annotation traces and text rendering.

An AnnotationTrace is immutable and identifies both its overlap and annotator. Reconstruction builds it after annotation from the fact memo, rule results, and the small amount of live state in TraceRecorder. Optional event collections use empty tuples so consumers can iterate without special cases.

ensembl.vep.trace.reconstruct module#

Reconstruct annotation traces from completed fact evaluation.

The fact memo, rule set, and fired terms provide most of a derivation after annotation. Live recording retains only read counts, cache origins, and the partial assignment used by staged annotation because those values cannot be recovered by replay.

Fact origins are reconstructed as follows:

  • computed – in the memo, and no cache claimed it.

  • prefilled / cached – in the memo, and the recorder says which cache put it there.

  • forced False – False in the staged assignment and absent from the memo, so it was proved False by requires propagation without being computed.

Call memo_fact_events before reconstructing rules. Rule reconstruction reads facts again, so capturing read counts afterwards would include replay activity.

ensembl.vep.trace.run module#

Run-level aggregation of annotation traces.

AnnotationTrace describes one overlap. RunTrace aggregates fact use, charged and avoided costs, reached cost tiers, and emitted terms across a run. It remains separate from the lightweight term-level RunSummary because fact-level tracing is optional and more expensive.
