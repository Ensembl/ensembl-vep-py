ensembl.vep.caches.feature_pool module#

The cross-payload feature pool contract, and the transcript pool that implements it.

BinnedFeatureCache (the worker’s per-payload transcript cache) is cleared before every new payload, so a worker that revisits the same gene across many payloads – a dense or targeted input, or simply a long run of variants on one chromosome – rebuilds the same Transcript from GXF records every time. Building one is not free: grouping records, constructing Exon/Translation objects, and resolving the shared Gene.

Transcript objects are never mutated after GXFTranscriptSource builds them, so reusing the same object across payloads is safe – the only growth over a transcript’s pooled lifetime is whatever cached_property values get resolved on it (introns, spliced sequence, CDS, translated sequence, and so on), which is why the pool is bounded by bytes rather than kept forever.

TranscriptPool is keyed by (region, stable_id, start, end) – the same fields BinnedFeatureCache already uses as its own dedup key – and mirrors ZoneMapCache’s byte-budgeted LRU shape: build outside the pool, insert and evict under a lock.

class ensembl.vep.caches.feature_pool.TranscriptPool(*, max_bytes=134217728)[source]#

Bases: FeaturePool[Transcript]

A byte-budgeted, least-recently-used cache of built Transcript models.

Reuse across payloads within one worker – a payload’s own BinnedFeatureCache is still cleared every time (BufferedWorker._begin_payload); this pool is what survives that clear. Construct one per worker and hand it to GXFTranscriptSource.transcript_pool.

Only one sequence region is held at a time: inserting a transcript from a different region than the one currently pooled drops every entry from the old region first. A sorted VCF input visits one region for a long run of payloads before moving to the next, so this keeps the common case (many payloads over the same region) cheap without holding memory for regions no longer being annotated. It is a size optimisation, not a correctness requirement – a transcript is always addressed by its full key, so nothing breaks if the same region is revisited later; it is just a pool miss.

eq=False keeps identity semantics: this is a shared, mutable instance, not a value object, so two pools with equal counters must not compare equal.

Variables:

  • max_bytes (int) – Byte budget for pooled transcripts. <= 0 disables the pool: get always misses and put never stores anything. Default is DEFAULT_TRANSCRIPT_POOL_BYTES.

  • hit_count (int) – Number of get calls served from the pool so far.

  • miss_count (int) – Number of get calls that found nothing so far.

  • eviction_count (int) – Number of entries evicted for being over the byte budget so far.

  • seq_region_eviction_count (int) – Number of entries dropped so far because the pooled seq_region changed.

ensembl.vep.caches.zone_map module#

Cache transcript geometry as positional-fact zones.

Zone boundaries partition a transcript and its flanks into spans with constant positional facts. Each zone stores a fact bitmask, allowing variant spans to be evaluated with a binary search and short bitwise union instead of repeated interval scans. Allele-dependent sequence facts remain outside the zone map.

ZoneMapCache reuses maps across variants and evicts least-recently-used maps by estimated byte size. Computed facts are inserted through FactContext.prefill without charging their normal evaluation cost.

ensembl.vep.caches.zone_map.DEFAULT_ZONE_MAP_BYTES = 268435456#
