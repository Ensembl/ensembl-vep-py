ensembl.vep.sources.file.vcf.variation module#

VCF-backed variation feature sources.

Two of them, differing only in what a record is: VCFVariationSource reads parsed records, and PicklableVCFVariationSource reads the input’s own lines, which is what an annotation run needs because a record it hands a worker has to pickle.

class ensembl.vep.sources.file.vcf.variation.PicklableVCFVariationSource(*, sequence_source=None, slice_cache=WeakSliceCache(), file_path, sequence_region_resolver=None)[source]#

Bases: VCFVariationSource

VCF variation source whose records are the input’s own lines.

An annotation run reads in one process and builds models in another: the process driving the run reads records and the worker annotating them turns records into variations. A record has to pickle to make that crossing, which the Rust parser’s VCFRecord does not, and output has to echo the input’s own text back, which a record built from a line can no longer give. The line is both, so this source’s record is a line – narrowing the record type its parent reads, and leaving everything about building models from them the same.

Nothing here batches. iter_all_records yields one record at a time and whoever drives the source groups them (workflow.executor.PayloadIterator), which is what lets a format say what a record is without also deciding how many of them cross a process boundary at once.
