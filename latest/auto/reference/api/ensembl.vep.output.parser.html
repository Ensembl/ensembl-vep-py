ensembl.vep.output.parser.vcf module#

Annotated VCF consequence parsing.

VEP writes them as CSQ and SnpEff as ANN: one INFO field whose layout the header’s Description declares, one entry per (allele, feature) separated by commas, fields by pipes, several terms by &. Both are read the same way; only the field names differ.

Two mechanics that must stay right, both confirmed on this codebase:

  • seed_attrs takes the public name and prepends the underscore itself: seed_attrs(overlap_consequences=...), never _overlap_consequences.

  • transcript_variation_alleles carries on_setattr=invalidates("_overlap_consequences"), so assigning it after seeding silently wipes the seed. This reader never assigns it, which is also why it needs no --gff/--fasta: the terms live on the allele, and Variation.most_severe_consequence and .class_so_term answer with zero transcripts.

ensembl.vep.output.parser.vcf.ANNOTATION_FIELDS = {'ANN': ('Allele', 'Annotation'), 'CSQ': ('Allele', 'Consequence')}#

INFO key -> the names of its allele and consequence fields, as each tool spells them.

ensembl.vep.output.parser.vcf.UNKNOWN_RANK = 999#

Rank given to a term the catalogue does not model. Rank 1 is the most severe and the model’s default is 0, so an unranked term must sit below every real one rather than above.
