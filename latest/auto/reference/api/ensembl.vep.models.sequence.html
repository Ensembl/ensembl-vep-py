ensembl.vep.models.sequence.mapper module#

Genomic <-> CDS <-> protein coordinate mapping for a coding region of a transcript.

Built from a transcript’s CDS genomic spans and strand only. Stays reusable outside a Transcript entirely.

Always builds a small (O(exon count)) bisect index at construction: - prefix sums over the spans, walked in transcript order (reversed on the reverse strand) - the span in genomic ascending order and related prefix sums.

Can optionally use a fully-expanded offset<->position index for O(1) lookups, at the cost of higher memory usage. Measured ~15MB for a titin-scale (109 kb, 363-exon) CDS, against ~52 KiB for using bisect. A byte-budget LRU caches/mapper_cache.py can limit memory usage for the index.

class ensembl.vep.models.sequence.mapper.Mapper(*, genomic_spans, strand, coding_start_offset, coding_end_offset, padding=0)[source]#

Bases: object

Genomic <-> offset coordinate mapping over an ordered list of genomic spans.

Deliberately generic: the spans can be a transcript’s CDS blocks (Transcript.cds_mapper), its whole spliced exon set (Transcript.cdna_mapper), or any other ordered block list. “Offset” therefore means whatever the caller built the mapper from, CDS-relative in the first case, cDNA-relative in the second.

The exception is the codon and protein methods (codon_window, codon_genomic_spans, offset_to_protein_offset, protein_offset_to_span). Those divide offsets by three and so only mean anything on a mapper built over CDS spans; calling them on a cDNA mapper is a caller error, not something this class can detect.

padding offsets come before the first genomic base and map to none. A CDS whose 5’ end is incomplete starts part-way through a codon; VEP pads it with that many N so the reading frame, the codon numbering and the CDS positions it reports all count from a whole codon.

Variables:

  • genomic_spans (list[tuple[int, int]]) – The genomic spans, in transcript (5’ to 3’) order. Index 0 is always the first span. Genomic-descending on the reverse strand.

  • strand (Strand) – The owning transcript’s strand.

  • coding_start_offset (int) – 0-based offset to the first coding base

  • coding_end_offset (int) – 0-based offset to the last coding base

  • padding (int) – Offsets before the first genomic base, 0 for a CDS starting on a whole codon.

genomic_span_to_offsets(min_position, max_position)[source]#

Map a genomic span [min_position, max_position] to CDS/cDNA offsets [low, high].

Equivalent to calling genomic_to_offset on every genomic position in the span and taking the min/max of whatever is overlapping the CDS/cDNA. But instead of calling for every genomic position in the span, this uses a bisect search to find the overlapping coding spans and then calculates the offsets from the span’s prefix sums and the portion overlapping with the span.

Suitable for a variant’s genomic span, which may be very large if it is structural.

Parameters:

  • min_position (int) – Lower bound (inclusive) of the genomic span, 1-based.

  • max_position (int) – Upper bound (inclusive) of the genomic span, 1-based.

Returns:

(low, high) 0-based CDS/cDNA offsets, or None if the span touches

no CDS/cDNA spans at all.

Return type:

tuple[int, int] | None

subseq(start, end, strand=Strand.FORWARD)[source]#

Return the sequence of a span given in slice-relative coordinates.

A span inside a linear, source-backed slice is read straight from the source, so a feature on a whole-chromosome slice never materialises the chromosome. Anything else – a circular slice, whose span may wrap the origin, or a span reaching outside this one – is cut from seq.

Parameters:

  • start (int) – Span start relative to the slice, 1-based inclusive.

  • end (int) – Span end relative to the slice, 1-based inclusive.

  • strand (Strand, default: Strand.FORWARD) – Orientation of the returned sequence relative to the slice.

Returns:

The span sequence, or None if the slice has no sequence or no strand to

measure the span against.

Return type:

str | None
