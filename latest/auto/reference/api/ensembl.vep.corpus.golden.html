Load pinned corpus files and terms, or explicitly generate a missing fallback.

Existing but malformed data always raises. Generation is limited to absent data so a corrupt golden reference cannot silently validate against newly generated expectations.

  • directory (Path | None, default: None) – Explicit bundle directory, or None for packaged data.

  • fallback (CorpusSpec | None, default: None) – Corpus to annotate when missing data may be generated.

  • allow_generate (bool, default: False) – Whether an absent dataset may use fallback.

ensembl.vep.corpus.golden.terms module#

Frozen expected terms emitted for a corpus and pinned to a file.

Conformance proves every annotator agrees with consequence.linear. It cannot catch all of them agreeing on the same wrong answer; a golden file can. It freezes the terms one annotator produced for one corpus, together with the corpus spec and the catalogue that produced them, so a later run is checked against a fixed expectation rather than only against itself.

Named golden on purpose: in this repository “oracle” already means the external Perl VariationEffect.pm, whose whole value is that it is not us. This is the opposite thing.

A mismatch is reported three distinct ways, because each calls for a different response. The catalogue changed under the file – regenerate it, deliberately. The file was recorded for another corpus – it is the wrong file. Or the terms moved with neither changed – a regression.

ensembl.vep.corpus.golden.terms.FORMAT_VERSION = 1#

Bumped whenever the file layout changes, so an old file is rejected rather than misread.

Return the key an overlap is filed under: its feature, then its variant’s name.
