ensembl.vep.workflow.tracks.base module#

Annotation-track contracts and value objects.

A track owns everything one kind of annotation needs: the source it reads, whatever it caches between payloads, the rule pairing features with alleles, the annotator interpreting each pair, and where the results are attached for output. The worker running a track supplies only what every track shares – the reference sequence and the synonym map – so adding a kind of annotation adds a track and changes nothing above it.

ensembl.vep.workflow.tracks.custom module#

Custom annotation tracks.

A placeholder: CustomOverlapFinder and the CustomFeature model exist, but no reader parses a --custom spec, so a run that asks for one is told rather than quietly annotating without it. --custom is repeatable, so this is the builder that returns one track per occurrence once the readers exist.
