ensembl.vep.explain package#

Overlap selection, annotation, comparison, and summaries for vep explain.

Separate from runner/explain.py, which is only the subcommand: reading the options, choosing which rendering was asked for, and writing it out. Everything a second caller could want – naming and finding the overlaps of a real input, annotating one with tracing on, diffing two derivations, summarising an overlap – lives here.

The package sits above trace: a trace is recorded during annotation, and these modules read one afterwards.

ensembl.vep.explain.compare module#

Comparison of traced derivations and assigned terms.

Comparing two traces identifies the first differing fact value, rule verdict, or subsumption path, rather than reporting only different emitted terms. diff_terms compares a trace with terms from an annotator or an already-annotated input when the other side cannot provide a trace.

ensembl.vep.explain.selection module#

Overlap selection for consequence explanations.

Explaining one derivation needs one (variant, transcript) pair out of a real input, which is a different job from annotating a whole file: there is no buffering, no output, and reading the whole input to pair every variant would be waste when the caller named one. What it must not be is a second opinion about which pairs exist – so the pairing here is built by the transcript track’s own build_transcript_overlap_finder over the same sources the run path builds, and only the search is explain’s own.

The two kinds of source answer the same question differently: a file is searched for the named variant alone, pairing no more of it than that takes, while a generated corpus is walked, there being nothing to query. OverlapSelection holds that choice for one run, reading each source lazily and at most once, so selecting by name costs one pass and selecting nothing costs none.

Yield every selectable overlap, in the order --index counts.

Pairing every variant means reading both files whole: an un-indexed GFF3 or GTF cannot serve a region query at all, and a caller asking for the listing has asked for all of them. The transcripts are grouped by sequence region once, rather than queried per variant, which is what keeps this one pass over each file.

class ensembl.vep.explain.selection.VariantSelector(*, seq_region_name, position, reference_allele=None, alternate_allele=None, identifier=None, allele_num=1)[source]#

Bases: object

Variant selector written as CHR:POS:REF>ALT or CHR:POS:ID.

The two forms locate a variant differently. REF>ALT names one allele by its minimised coordinates, as the model stores them. ID names a record by the identifier and position the input gives it – a VCF’s ID and POS columns – and allele_num picks one of its alternate alleles.

Variables:

  • seq_region_name (str) – Sequence region name.

  • position (int) – The allele’s start for REF>ALT, the input’s own position for ID.

  • reference_allele (str | None) – Upper-cased reference allele, "" when empty; None for ID.

  • alternate_allele (str | None) – Upper-cased alternate allele, "" when empty; None for ID.

  • identifier (str | None) – The variant’s identifier in the input; None for REF>ALT.

  • allele_num (int) – Which alternate allele an ID selects, counting from 1.
