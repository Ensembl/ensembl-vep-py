ensembl.vep.bench package#

Benchmarking: the conformance gate, timing, the strategy matrix, sweeps, results and the Perl oracle.

Measurement only. The corpus a benchmark runs over is ensembl.vep.corpus’s, not something this package owns; the runners in ensembl.vep.runner.bench are the command line on top.

Submodules#

ensembl.vep.bench.baseline module#

Benchmark results on disk, and comparing a run against an earlier one.

A number without its context is not comparable, so a results file carries what produced it: the corpus spec and its parameter hash, the git revision and whether the tree was dirty, the machine, and the timing policy. A comparison across two different corpora is refused rather than reported.

Timings regress past a threshold. The declared cost per overlap is deterministic, so any change in it is a change in behaviour – reported as such, and not held to a threshold.

ensembl.vep.bench.endtoend module#

Timing whole runs of the command line, one configuration at a time.

bench matrix times an annotator over overlaps that are already built. This times what a user runs: reading the VCF, loading transcripts from the indexed GFF3, fetching sequence, annotating, and writing the output. The difference between the two is the point – a strategy that wins several times over in isolation moves the end-to-end number by whatever share of the run annotation is.

Each run is a fresh process, so no configuration is timed against another’s warmed module state, and the process cost a real run pays is counted rather than amortised away. The child is given this tree on PYTHONPATH, so the benchmark measures the working copy it was started from and never an ensembl-vep installed elsewhere.

ensembl.vep.bench.harness module#

Measuring an annotator: the conformance gate that runs before any timing, and the timing itself.

The gate comes first on purpose. A strategy that is fast because it is wrong is not a result, so a benchmark refuses to time anything until every candidate agrees with the reference on every overlap. The gate returns a report rather than exiting: the runner decides what a mismatch means for the process.

ensembl.vep.bench.oracle module#

The Perl oracle: the same cases through our annotators and through VariationEffect.pm.

The oracle is the external reference – the whole point is that it is not us – so a disagreement is reported, never gated on. The Perl script tests only the coding, intronic, upstream and downstream categories, so the comparison asks whether our terms cover the Perl ones, not whether they are equal.

Coverage is counted twice, because the direct count undercounts agreement. The Perl script reports raw predicates, while our annotators emit terms after subsumption: an intronic variant in the polypyrimidine tract emits splice_polypyrimidine_tract_variant, which suppresses the intron_variant the Perl side reports. Counting the terms our emitted ones suppress, through the catalogue’s subsumes chains, separates that from a real disagreement.

The case list here and build_cases in bench/variation_effect.pl must stay aligned by name and order; CASE_NAMES is what a test pins against the Perl file. The transcript is built with the corpus’s own build_transcript, so its translation is derived exactly as the suite’s is – the hand-rolled builder this replaces had fallen out of step with the model and no longer ran.

ensembl.vep.bench.oracle.CASE_NAMES = ('coding_exact', 'coding_near_boundary', 'intron_primary', 'intron_secondary', 'upstream_near', 'upstream_far', 'downstream_near', 'downstream_far', 'no_hit')#

ensembl.vep.bench.sweep module#

Sweeping one numeric annotation setting and timing each value.

Every value is sanity-checked against the reference strategy before it is timed: a setting that changes the answer is a bug, not a speed-up. The chunking follows the strategy. A Python batch strategy chunks internally by its own batch_size, so it is handed the whole corpus at once; the native kernels chunk nowhere else, so for them the swept batch size is the chunk handed over.

ensembl.vep.bench.sweep.SANITY_CHECK_COUNT = 64#

Overlaps each swept value is checked on before it is timed.

ensembl.vep.bench.workspace module#

The corpus on disk: written, indexed, annotated against, and removed again.

An end-to-end benchmark needs what a real run needs – a VCF, a bgzip-compressed and tabix-indexed GFF3, and a FASTA with a .fai beside it – because an unindexed source takes a different code path, and timing that path would answer a different question.

Everything this module writes is recorded as it is written, so clean() can remove exactly what this invocation created and nothing else. A corpus already in the directory is reused and left alone, which is what makes --corpus_dir safe to point at a corpus worth keeping.

ensembl.vep.bench.workspace.INDEXING_TOOLS = ('bgzip', 'tabix')#
