classmethod for_command(command, **options)[source]#

Return the configuration for one command, named as the command line names its options.

The command’s own sections decide where each option belongs, so a caller gives flat option names and never has to know which section declares which. Values are coerced as the command line coerces them, so a path may be given as a string.

Parameters:

  • command (str) – A registered command, such as run.default.

  • **options (object) – Option values, named by field or by flag.

Returns:

The command’s sections built from these options, every other section left at

its defaults.

Return type:

Config

Raises:

ValueError – If the command is not registered, or an option is not one it reads.

Bases: object

How one option is exposed.

Variables:

  • help (str) – One-line description, used as the argparse help text.

  • flag (str | None) – Long flag spelling without the dashes, or None for the field name.

  • short (str | None) – Single-character short flag, without the dash.

  • synonyms (tuple[str, ...]) – Further long spellings that set the same option, for the names Perl VEP uses. They work on the command line and in a config file; the environment variable keeps the canonical name.

  • constants (Mapping[str, object]) – Flags that set this option to a fixed value, such as Perl VEP’s --vcf for --output_format vcf, as flag name -> value.

  • choices (Sequence[object] | Callable[[], Sequence[object]] | None) – The permitted values, or a callable returning them for a vocabulary another package owns.

  • metavar (str | None) – argparse metavar override.

  • env (str | None) – Environment variable name, or None to derive one.

  • hidden (bool) – True to keep the option out of --help.

  • repeatable (bool) – True for a tuple option given once per item, as Perl VEP’s --custom is. Each occurrence is kept whole, with no comma splitting.

ensembl.vep.config.report module#

The formats a report can be rendered in, and which of them a request can combine.

One vocabulary for every reporting command, so --output_format means the same thing to explain, catalogue, corpus and bench. A report is a table unless --graph asks for a diagram, and a format belongs to one kind or the other: resolution refuses the combinations that cannot be drawn rather than quietly rendering something else.

ensembl.vep.config.report.GRAPH_FORMATS = ('svg', 'dot', 'mermaid')#

Formats that render a diagram. svg is wrapped in a navigable HTML document.

ensembl.vep.config.report.REPORT_FORMATS = ('text', 'markdown', 'confluence', 'html', 'svg', 'dot', 'mermaid')#

Every format --format accepts, whichever kind the command can render.

ensembl.vep.config.report.TABLE_FORMATS = ('text', 'markdown', 'confluence', 'html')#

Formats that render rows.

ensembl.vep.config.sources.coerce_layer(layer, section_types)[source]#

Coerce every value in a layer to its declared type and check it against its choices.

Unknown sections are dropped silently, since a layer may cover sections the command does not read. An unknown field in a known section is dropped with a warning.

Raises:

ValueError – If a value cannot be read as its declared type or is not a permitted choice. The message names the section and field.

Return type:

dict[str, dict[str, object]]

Coerce a value read from a file or the environment to a field’s declared type.

Command-line values have already been converted by argparse. These have not: TOML gives real ints and bools but strings for paths, and the environment gives strings for everything.
